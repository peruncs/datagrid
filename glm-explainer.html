Eclipse DataGrid · Aeron clustering  //  explainer

One writer, many readers — no Kafka, no Raft.

Eclipse Store commits are packaged into a fixed binary envelope, published over Aeron UDP, durably recorded by an embedded Archive, and replayed by readers through PersistentSubscription. The commit is acknowledged to the application only after the Archive has recorded it. Crash recovery is conservative: ambiguous states fail closed with RESEED_REQUIRED rather than guessing.

topology 1 writer / N readers consensus none transport UDP · dynamic MDC log Aeron Archive ordering journal-first migration Kafka ⇄ Aeron SPI

01Key ideas

Five decisions that shape everything else.
AOpaque bytes, thin envelope

Eclipse Serializer stays the only object format. The wire protocol adds only routing, ordering, chunking and checksums — it never models your object graph.

Binary (Serializer) → AeronReplicationEnvelope → Aeron
BArchive is the WAL

The recorded publication is the source of truth for recovery. Readers replay it; the writer acknowledges a commit only after RecordingPos passes the commit marker.

addRecordedExclusivePublication · RecordingPos · awaitRecorded()
CJournal-first commit

Archive the prepared transaction → ask the local Store to accept it → archive a COMMIT marker. A failed local write emits ABORT. Ambiguous outcomes never reuse a sequence.

AeronStorageBinaryTargetDistributing → WriteCoordinator
DReaders replay-then-live

PersistentSubscription replays from a durable cursor, then seamlessly switches to live UDP. Chunks are staged in native memory and released to the Store only after a matching COMMIT + CRC.

PersistentSubscription · TransactionAssembler · EnvelopeView
EFail closed, never invent

Non-terminal checkpoint states (PREPARING, ENQUEUED, COMMITTING_UNCERTAIN) are not recoverable today → startup reports RESEED_REQUIRED. No silent skip, no duplicate, no invented sequence.

AeronReplicationCheckpoint · State · ReplicationHealth

09Why CRC32C & what didn't we do

ΣTwo CRCs, two jobs

Chunk CRC catches a torn/partial frame at the fragment boundary before the assembler allocates or stages. Commit CRC is the whole-Store-binary witness — the reader only releases a transaction when the assembled bytes match the commit marker, and the writer stores it in the checkpoint as the restart identity.

Cheap (java.util.zip.CRC32C, vectorized, bulk scratch buffer) — and deliberately not authentication. Network isolation/fencing is the boundary, not the envelope.

×Explicitly not built

No Aeron Cluster/Raft, no leader election, no SBE codegen, no compression, no TLS in the envelope, no ACK-driven retention (until authenticated reader watermarks exist), no LOCAL_DURABLE_FIRST (Store has no durable-completion callback), no independent Archive process (yet), no power-loss proof.

Each one is a documented, deliberate deferral — most are gated by real design questions, not missing effort.
